FlowBridge Event-Driven Snowflake Platform

A Snowflake-native supply-chain data platform for a fictional equipment distributor: Azure storage events trigger Snowpipe, and Streams, Tasks, stored procedures and Dynamic Tables build a governed Bronze, Silver and Gold model behind secure views.

Business problem and objectives

Supply-chain operations need reliable visibility into orders, revenue, products, suppliers, warehouses, inventory activity and shipments. Raw operational data is hard to analyse directly. It has inconsistent structures, duplicate records and fields that are not shaped for analysis.

Objectives

  • Replace manual reporting with automated, event-driven loading.
  • Cleanse and model raw operational JSON into governed, analytics-ready tables.
  • Serve results through secure, role-controlled views and a Streamlit application.

System architecture

Python and Faker generate nested JSON into ADLS Gen2. Azure Event Grid and a storage queue trigger Snowpipe, which loads Snowflake automatically. Streams, Tasks and stored procedures move data through Bronze, Silver and Gold. Secure views serve the curated results to a Streamlit dashboard.

How the platform works

  1. Bronze: raw ingestion with load metadata, preserving the source structure.
  2. Silver: type standardisation, deduplication, cleansing, null handling and flattening of nested operational structures, in two stages.
  3. Gold: a star schema of facts and dimensions (customers, products, suppliers, warehouses, shipments) with surrogate keys and SCD Type 1.
  4. Serving: secure views and business-ready metrics for the dashboard.

Engineering decisions

  • Event-driven loading through Event Grid and Snowpipe follows file arrival and does not poll.
  • Streams track changes so later layers can process only what is new.
  • Dynamic Tables keep selected analytical datasets maintained declaratively.
  • SCD Type 1 keeps current values only. It is simpler than Type 2, and it gives up history.
  • Role-based access and secure views control what consumers can see, and development and production are kept separate.
  • Inventory movement is calculated as a proxy metric. It is not conventional inventory turnover.

Reliability, testing and data quality

Validation is built into the pipeline: required fields, data types, duplicates, referential relationships and business rules. Verification SQL is kept in sql/09_resume_and_verify.sql. The latest repository version was rerun successfully in Snowflake on 8 November 2026.

Deployment and operations

Nine numbered SQL scripts run in order, from account setup through Bronze, Silver, Gold, serving and governance to DEV to PROD deployment and verification. Deployment and governance are documented in the docs/ folder. I reran the latest version of the repository in Snowflake on 8 November 2026, and it completed successfully.

Results and implementation evidence
