Projects

AtlasFlow: Real-Time Logistics Control Tower

PostgreSQL, Debezium, Apache Kafka, Apache Flink SQL, Apache Iceberg, Trino, Apache Superset, Docker Compose

Problem: Operations teams need current shipment status, but batch reporting lags behind changes in the source database.

What I built: Captured PostgreSQL changes with Debezium and Kafka, then ran three Flink SQL streaming jobs that write Bronze, Silver and Gold Iceberg tables.

Result: Gold holds one current record per shipment, updated by key, with a rule-based risk classification. Runs end to end in Docker Compose on synthetic data.

HealthGrid Data Platform

Azure Data Factory, Azure Databricks, PySpark, Azure SQL, PostgreSQL, ADLS Gen2

Problem: Repeated, missed or overwritten source loads leave inconsistent records.

What I built: Azure SQL control tables choose a FULL, APPEND or MERGE load for each source. Watermarks and a file manifest block repeat loads. MERGE rejects null or duplicate keys and updates a row only when the incoming version is newer.

Result: Every stage is audit-logged from landing to Gold. Runs end to end in Azure on synthetic data.

Uber Eats Data Analytics Platform

Azure Data Factory, ADLS Gen2, Azure Databricks, PySpark, FastAPI, Python

Problem: Data from REST APIs, CSV files and SQL sources arrives in different formats and needs one reliable reporting layer.

What I built: Three metadata-driven Data Factory pipelines load into ADLS Gen2. Databricks PySpark builds the Bronze and Silver layers, then publishes Gold with reconciliation checks.

Result: Checkpointed incremental loads and recovery runbooks. Deployed and run end to end in Azure on synthetic data.

NovaCart Incremental Retail Lakehouse

Azure Databricks, Delta Lake, PySpark, Azure SQL, Databricks Jobs

Problem: Retail order data changes constantly, and order history has to stay accurate.

What I built: Bronze, Silver and Gold layers loaded incrementally, using timestamp and key watermarks in a control table. Delta MERGE and SCD Type 2 keep order history. A Databricks Job runs the layers in sequence.

Result: A repeatable workflow that can be rerun safely. Resources were shut down after the run to control cost.

FlowBridge Snowflake Project

Snowflake, Snowpipe, Streams and Tasks, ADLS Gen2, Streamlit

Problem: Files landing in cloud storage must reach the warehouse automatically and be ready for dashboards.

What I built: Event-driven ingestion from Azure into Snowflake with Bronze, Silver and Gold layers, a star schema (SCD Type 1) and a Streamlit dashboard.

Result: Latest version reran successfully in Snowflake on 8 November 2026. Synthetic data.

CFPB Consumer Complaint Analytics

Microsoft Fabric, PySpark, Fabric Warehouse, Power BI

Problem: Shows how complaint volumes change over time, which products, issues and companies generate the most complaints, and how often companies respond on time.

What I built: Bronze, Silver and Gold layers in Microsoft Fabric. Kaggle API and a Fabric pipeline load the CFPB CSV into a Bronze Lakehouse. PySpark profiles and cleans it into Silver. A stored procedure loads the Gold fact and dimension tables into a Fabric Warehouse. A semantic model feeds a three-page Power BI report.

Quality: Records where the date sent precedes the date received are quarantined. Silver holds 896,931 records and quarantine holds 7,052, reconciling to the 903,983 source records.

Result: Run end to end in Fabric with a DEV-to-PROD deployment. Uses real CFPB complaint data.
